# Split Decision: Learning Design Brief

## Experience summary

Split Decision is a seven-level Grade 6 interactive prototype about expressions,
grouping, and equivalence. Learners compare two ways of ordering the same pizzas:
one combined checkout with one delivery fee, or two separate checkouts with two
delivery fees. The familiar situation makes the scope of multiplication visible
before formal symbolic language is introduced.

## Backward-design target

By the end of the experience, a learner should be able to explain why
`2(x + 3)` and `2x + 3` represent different cost structures, why
`2(x + 3) = 2x + 6`, and why testing one value is not sufficient to prove that
two expressions are equivalent.

## Standards alignment

- CCSS 6.EE.A.2: Write, read, and evaluate expressions
- CCSS 6.EE.A.3: Apply properties of operations to generate equivalent expressions
- CCSS 6.EE.A.4: Identify when two expressions are equivalent

## Learning progression

1. **Notice:** Compare totals for one combined order and two separate orders.
2. **Represent:** Match each checkout arrangement to an expression.
3. **Decompose:** Expand two complete receipts into repeated costs.
4. **Generalize:** Change the pizza price and identify the invariant difference.
5. **Disprove:** Find a counterexample to a false equivalence claim.
6. **Transfer:** Apply the same structure to tickets and per-ticket booking fees.

## Anticipated misconceptions and responses

| Learner idea | Experience response |
| --- | --- |
| The same items must always have the same total. | The learner runs both checkouts and sees the repeated fee attach to each active order. |
| `2(x + 3)` means `2x + 3`. | Two receipts make both the pizza and fee visibly repeat. |
| The distributive property changes only the variable term. | Receipt lines expand into `x + 3 + x + 3`, then combine into `2x + 6`. |
| One matching input proves equivalence. | A counterexample challenge asks the learner to choose another input that breaks the claim. |
| The pizza story is the mathematics. | The final level transfers the structure to ticket prices and booking fees. |

## Interaction principles

- Begin with a decision, not a definition.
- Let system behavior carry the first layer of feedback.
- Reveal notation after learners have acted on the represented quantities.
- Respond to likely reasoning, not only answer correctness.
- Include a transfer task so success requires structural understanding.

## Prototype status

This is an independent portfolio prototype intended for critique and playtesting.
It demonstrates interaction, learning progression, feedback strategy, and visual
direction; it is not a production-complete or commissioned product.
